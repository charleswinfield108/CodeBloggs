# Skeleton Loader Documentation

## Overview and Purpose

The Skeleton Loader is a React component implemented in [client/src/components/SkeletonLoader.jsx](../client/src/components/SkeletonLoader.jsx) that serves as a placeholder UI element to improve perceived performance while data is being fetched from the server. It displays animated skeleton screens that mimic the layout of actual content, creating a smooth loading experience for users. The component accepts two props: `type` (defaulting to "post") which determines the skeleton layout style, and `count` (defaulting to 10) which controls how many skeleton placeholders are rendered. The skeleton elements use a CSS pulse animation that fades opacity between 1 and 0.5 every 2 seconds, providing visual feedback that content is loading.

## How It Works and Skeleton Types

The SkeletonLoader renders three distinct skeleton types depending on the `type` prop: **"post"** skeletons display a two-column layout with an author info section on the left (avatar, name, date, status) and content section on the right (three lines of text and placeholder buttons), mimicking blog post layouts. **"card"** skeletons render individual cards in a responsive grid with an avatar, name, role, biography lines, and an action button—used for displaying profile information. **"user"** skeletons generate table rows with multiple columns of placeholder data, designed for tables in administrative interfaces. All skeleton elements share a common base style with light gray backgrounds (#D3D3D3), rounded corners, and the pulse animation. The component dynamically generates as many skeletons as specified by the `count` prop, and uses conditional rendering to display the appropriate HTML structure (divs for posts/cards, table rows for users).

## Implementation and Usage

The SkeletonLoader is exported as a default export from [client/src/components/SkeletonLoader.jsx](../client/src/components/SkeletonLoader.jsx) and is imported and used throughout the application in data-loading scenarios. It appears in [client/src/pages/Blogs.jsx](../client/src/pages/Blogs.jsx) (post type with 5 skeletons), [client/src/pages/Home.jsx](../client/src/pages/Home.jsx), [client/src/pages/Admin.jsx](../client/src/pages/Admin.jsx) (card type with 2 skeletons), [client/src/pages/Network.jsx](../client/src/pages/Network.jsx) (card type with 6 skeletons), [client/src/pages/ContentManager.jsx](../client/src/pages/ContentManager.jsx), and [client/src/pages/UserManager.jsx](../client/src/pages/UserManager.jsx) (user type with dynamic count). Developers conditionally render the SkeletonLoader while data is being fetched and replace it with actual content once the API call completes, creating a professional loading state that matches the final content's visual structure.
