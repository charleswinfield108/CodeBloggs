# Content Manager Pager Documentation

## Overview and Client-Side Pagination Architecture

The Content Manager implements a client-side pagination system in [client/src/pages/ContentManager.jsx](../client/src/pages/ContentManager.jsx) that allows administrators to browse, filter, and manage all posts across multiple pages. Unlike server-side pagination, the Content Manager fetches all posts from the backend via `/posts` endpoint and performs pagination calculations on the client side, enabling efficient filtering by date range without requiring additional server requests. The pagination workflow begins with the `fetchPosts()` function fetching all posts and users data, then filtering by optional `startDate` and `endDate`, sorting posts by creation date (newest first), and finally calculating pagination using `skip = (page - 1) * itemsPerPage` with Array slice to extract the current page's posts. The component maintains state variables: `currentPage` (current page number), `itemsPerPage` (posts per page, defaulting to 10), and `totalPosts` (total count of filtered posts), which work together with the array slicing logic `paginatedPosts = allPosts.slice(skip, skip + size)` to manage display.

## How Pagination Controls and Date Filtering Work

The pagination interface displays Previous/Next buttons and numbered page buttons that correspond to `Math.ceil(totalPosts / itemsPerPage)` total pages, allowing users to navigate through filtered results. When a user clicks a page button or navigation arrow, the `fetchPosts()` function is called with the target page number, which recalculates the slice indices to display the appropriate subset of posts. The component provides dynamic filtering through a date range picker with `startDate` and `endDate` inputs that trigger automatic re-fetching via a `useEffect` hook; when filters change, pagination resets to page 1 and `fetchPosts(1)` is called. The page size selector dropdown allows users to choose between 10, 20, or 30 posts per page via the `handlePageSizeChange(e)` function, which updates `itemsPerPage`, resets to page 1, and re-fetches with the new size. Pagination controls include proper state management: the "Previous" button disables when `currentPage === 1`, and the "Next" button disables when `currentPage === Math.ceil(totalPosts / itemsPerPage)`, preventing navigation errors. An "Select All" button clears date filters to display all posts.

## Files Required for Content Manager Page Functionality

The Content Manager page requires the following frontend component files to function: [client/src/pages/ContentManager.jsx](../client/src/pages/ContentManager.jsx) (main page with pagination), [client/src/components/Layout.jsx](../client/src/components/Layout.jsx) (page wrapper), [client/src/components/SkeletonLoader.jsx](../client/src/components/SkeletonLoader.jsx) (loading state for posts), [client/src/components/DeleteConfirmationModal.jsx](../client/src/components/DeleteConfirmationModal.jsx) (delete confirmation), [client/src/components/AvatarInitials.jsx](../client/src/components/AvatarInitials.jsx) (displays user avatars for post authors), [client/src/context/SessionContext.jsx](../client/src/context/SessionContext.jsx) (session and admin authentication), and [client/src/context/ToastContext.jsx](../client/src/context/ToastContext.jsx) (notification system). External dependencies include the `react-icons/fi` library for like and comment icons. The backend requires: [server/routes/post.routes.js](../server/routes/post.routes.js) (route definitions), [server/controllers/post.controller.js](../server/controllers/post.controller.js) (request handlers fetching and deleting posts), [server/routes/user.routes.js](../server/routes/user.routes.js) (user data endpoints for author information), [server/db/connection.js](../server/db/connection.js) (MongoDB connection), and the main server file [server/server.js](../server/server.js). The `/posts` endpoint returns all posts as an array, and `/post/:id` DELETE removes individual posts; additionally, `/users?limit=1000` endpoint provides user data mapped by user ID to display author information alongside paginated posts.
